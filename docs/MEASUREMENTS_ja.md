# 測定値とパラメータ — ESP32-C5 13/6 cm DATV ビーコン

[English](MEASUREMENTS.md) · [Italiano](MISURE_it.md)

以下の数値はすべて開発中(2026年11月15〜22日)に実機で測定したものです。
受信機: **ADALM-Pluto + leandvb**(DVB-S2 デコーダ)を使った Portsdown 系の局と **MiniTiouner**。
スペクトラム: Pluto ベースの表示、スパン 10 MHz。レベルは相対値(Pluto の dBFS)で校正していません。

## 1. 試験したハードウェア

| 項目 | 値 |
|---|---|
| ボード | Waveshare **ESP32-C5-Zero**(モジュール ESP32-C5HF4) |
| チップ | ESP32-C5 rev 1.0、Wi-Fi 6 デュアルバンド、RISC-V HP コア 1 個 240 MHz + LP コア |
| フラッシュ / PSRAM | パッケージ内 4 MB / **なし** |
| 水晶 | 48 MHz |
| RF 出力 | ANT_2G + ANT_5G → ダイプレクサ → **GPIO26** の RF スイッチ: Low = セラミック(基板)アンテナ、**High = IPEX** |
| LED | WS2812(GPIO27)・BOOT ボタン GPIO28 |
| 使用アンテナ | IPEX に広帯域アンテナ(2.4 / 5.7 GHz) |
| 開発環境 | ESP-IDF v6.1 |

## 2. C5 の I/Q 送信(実験で発見)

C5 用のベンダーライブラリには送信リプレイのコードが残っていない(`dactrig` が空)ため、以下のレジスタはすべて試験で見つけました。

| パラメータ | 値 |
|---|---|
| DAC リプレイ制御 | `0x600A900C`: [13:0] 長さ、bit19 ループ、bit31 開始、bit18 終了 |
| サンプル語 | I = bit 0–9、Q = bit 10–19(符号付き 10 bit)、スペクトラム**非反転** |
| サンプルレート | 80 MS/s(3.000 CPU サイクル/サンプル)、**bit17 = 40 MS/s**(6.000 サイクル) |
| ソース設定 | `0x600A9008` bit 17–20 = `0xF`(電源断で消えるため毎回の送信前に設定) |
| メモリバンク | 所有者レジスタ `0x60095004`: 0x200 → 0x40820000、0x400 → 0x40840000。エンジンは所有者の切替に即座に追従(2 秒で 10 万回のピンポンを確認) |
| 開始遅延 | 約 45–50 CPU サイクル、ばらつき ±10 |
| PLL 同調 | `phy_set_freq(MHz, kHz)` — 整数 MHz + kHz(1 kHz 単位) |
| 受け付けた周波数 | 2320、2375、5660、5760、5800 MHz でエラーなし |

### 3.3 水晶補正(2026/11/21、Pluto 受信機、各 60 秒送信、冷 → 温のオフセット)

| 試験 | バンド | 補正 | 受信オフセット | ロック |
|---|---|---|---|---|
| 1 | 13 cm | 0 ppm | +26.6 → +22.7 kHz | 連続(5 秒で) |
| 2 | 13 cm | +9.26 ppm | +4.6 → +0.5 kHz | 連続 |
| 3 | 6 cm | +9.26 ppm | +6.2 → −3.1 kHz | **断続**(信号が Pluto の DC = 0 Hz を横切る) |
| 4 | 6 cm | +6 ppm | +16.6 → +13.3 kHz | 連続 |

* 試験 1 と 2 の差 = −22.0 kHz = 設定した補正と一致 → `phy_set_freq` の第 2 引数が kHz であることを確認。
* 冷えた状態からの送信中の熱ドリフト: 約 1.6–1.7 ppm/分(13 cm で約 4 kHz/分、6 cm で約 9 kHz/分)。
* 採用値 **+7 ppm**: 両バンドで信号を受信機中心(Pluto の DC)より数 kHz 上に保つ。

## 4. エンコーダとタイミング(C5、シングルコア)

| 項目 | 値 |
|---|---|
| 検証 | Python 参照エンコーダと 42/42 フレーム一致、実時間経路 8/8 フレームでシンボル誤り 0 |
| 1 フレームの時間(CPU 空き) | BCH 2.72 + LDPC 2.34 + マッピング 3.11 = **8.2 ms**(333 kS で 1 フレームは 99.9 ms) |
| 実時間生成のコスト | 約 166 万サイクル/フレーム、1 ステップ ≤ 9000 サイクル(適応マージン) |
| バンク書込み(QPSK、H=8) | 切替ごとに 96 k サイクル中 60.3 k |
| 切替遅延 | 11/21 夜の試験で最大 4954–6114 サイクル。60 秒あたり 8–35 回の遅れ、DUMMY 0(調査中) |
| TS | 333 kS で 483 541 bit/s(60 秒で映像 8903、音声 2816、ヌル 4743 パケット) |
| 停止遅延(BOOT / STOP GPIO) | 256 回の切替ごとに確認 ≈ 80 ms |

## 7. 既知の制限

* PSRAM がないため、ESP32-S3 プロジェクトの受信「Parrot」は C5 に載りません。
* 送信中は Wi-Fi 無線が変調器になるため、ダッシュボードは休止中と設定モードでのみ使えます。
* テストカードは事前エンコード済みの H.265 ファイルです(C5 にビデオエンコーダはありません)。
* ウォームアップ中の周波数ドリフト(3.3 参照): 温度補償が次の段階です。
